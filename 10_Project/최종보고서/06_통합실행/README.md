# 06_통합실행 · 카메라 여러 대를 한 번에 판정하기

`알박기_실행.py` 하나로 **카메라(또는 영상) 여러 대 → 판정 → 신호등 · 기록 · 실시간 현황 화면**이 모두 돌아갑니다. 판정 규칙은 [04_BASE_MODEL](../04_BASE_MODEL)의 SAM 감지 범위 데모와 같은 코드(`room_logic.py`, `sam_zone.py`)를 그대로 불러 씁니다.

## 하는 일

1. 룸마다 카메라에서 **가장 최근 화면 한 장만** 받아 둡니다. 판정이 느려도 밀린 화면을 쌓지 않아 지연이 누적되지 않습니다.
2. `--interval`(기본 1초)마다 모든 룸을 차례로 판정합니다.
   - YOLO26s v2로 사람·테이블·짐 검출 → SAM 테이블 테두리 +15% 감지 범위 → 사람 박스가 10% 이상 겹치면 재석
   - 2초 연속 보이면 🔴 사용중, 10초 넘게 안 보이면 부재, 초록불 시간(기본 30분)이 지나면 🟢, **사람도 짐도 10초 넘게 없으면 바로 🟢**
   - 모델(YOLO·SAM)은 하나를 모든 룸이 같이 쓰고, 감지 범위와 타이머는 룸마다 따로 둡니다.
3. 색이 바뀌면
   - 신호등 주소로 `{"room": "3층-1", "color": "green"}`을 POST로 보냅니다 (`send_signal` 함수만 고치면 다른 방식으로 바꿀 수 있음).
   - 사람을 모자이크한 화면을 `결과/스냅샷`에 저장하고, 하루 지난 파일은 지웁니다.
4. 모든 판정을 `결과/판정기록.csv`에 남깁니다.
5. 브라우저에서 **http://localhost:8800** 을 열면 MVP 관제 대시보드와 같은 모양의 현황 화면이 뜹니다 (아래 "현황 화면").
6. 끝나면 한 바퀴(모든 룸을 한 번씩 판정) 처리 시간을 `결과/동시처리_결과.json`에 남깁니다.

## 실행

```bash
pip install ultralytics opencv-python pillow

# 1) 룸 14개 동시 처리 시험: 영상 하나를 룸 14개처럼 복제 (룸마다 다른 위치부터 재생)
python 알박기_실행.py --demo-video 1차.mp4 --demo-rooms 14 --duration 120 --open

# 2) 실제 운영: 룸 설정 파일 (rooms.example.json 참고)
python 알박기_실행.py --rooms rooms.json --signal-url http://신호등주소/signal --limit 00:30:00
```

### 초록불 시간 입력

시작하면 초록불로 바꿀 자리 비움 시간을 **시:분:초(00:00:00)** 로 묻습니다. 시험할 때 30분을 기다리지 않도록 짧게 줄여 씁니다.

```
초록불 시간: 00:01:30      ← 1분 30초 (000130 이라고 써도 됨)
초록불 시간: 00:00:20      ← 20초
초록불 시간:               ← 그냥 Enter = 00:30:00 (학교 규칙)
```

- 형식이 틀리면 다시 묻습니다 (`1:30`, `0130`처럼 자리 수가 모자라면 안 받음).
- **10초 이하로 하면 노랑이 보이지 않습니다.** 사람이 10초 연속 안 보여야 부재로 판정하는데, 그때 이미 초록불 시간이 지나 있어 빨강에서 바로 초록이 됩니다. 노랑까지 보려면 20초 이상으로 입력하세요.
- `--limit 00:01:30`으로 주면 묻지 않습니다. 입력을 받을 수 없는 실행(예약 작업 등)은 30분으로 시작합니다.
- 현황 화면과 성능 확인 창의 "30분" 글자도 입력한 시간으로 바뀌고, 시험 설정이면 "학교 규칙은 30분"을 같이 보여 줍니다.

| 옵션 | 기본값 | 뜻 |
|---|---|---|
| `--interval` | 1.0 | 모든 룸을 한 번씩 판정하는 간격(초) |
| `--overlap` | 0.10 | 사람 박스 중 감지 범위와 겹쳐야 하는 비율 |
| `--grow` | 0.15 | 테이블 테두리를 짧은 변의 몇 배만큼 부풀릴지 |
| `--limit` | 시작할 때 물어봄 | 초록불 시간 (`00:01:30` 또는 `000130`) |
| `--weights` | `../03_모델/알박기_yolo26s_v2.pt` | 판정 모델 |
| `--duration` | 0 | 이만큼(초) 돌고 끝냄. 0이면 Ctrl+C까지 |
| `--open` | | 현황 화면이 준비되면 브라우저로 열기 |
| `--no-web`, `--no-snapshot` | | 현황 화면·스냅샷 끄기 |

SAM 가중치(`sam2.1_t.pt`)는 처음 실행할 때 자동으로 받습니다. 원본 영상(1차.mp4)은 사람이 그대로 나와 저장소에 올리지 않았습니다.

## 현황 화면 (http://localhost:8800)

[04_BASE_MODEL/DEMO](../04_BASE_MODEL/DEMO)의 MVP 관제 대시보드와 같은 디자인으로, 시뮬레이션 대신 **지금 판정 결과**를 보여 줍니다. 화면 파일은 `현황/` 폴더(`index.html`, `app.js`, `style.css`)에 있고 `알박기_실행.py`가 같이 내보냅니다.

| 영역 | 보여 주는 것 | 갱신 |
|---|---|---|
| KPI | 사용 중 · 자리 비움 · 이용 가능(빈 책상 / 초록불 시간 넘은 짐) 룸 수, 지금 룸 활성화율, 초록불 시간 넘게 짐만 있는 룸, 한 바퀴 판정 시간 | 1초 |
| 룸 지도 | 룸마다 신호등 색, 사용 시작 시각 또는 비운 시간 · 초록까지 남은 시간, 켠 뒤부터의 상태 띠 | 1초 |
| 알림 | 초록불이 켜진 룸, 초록불 뒤 입실 (누르면 그 룸으로 이동) | 1초 |
| 판정 규칙 | 재석 10% 겹침 · 2초, 부재 10초, 초록불 시간(입력한 값) 뒤 초록, 빈 책상 바로 초록, SAM 테두리 +15% | 고정 |
| 선택한 룸 카메라 | **실시간 영상(초당 15장)** 위에 마지막 판정의 감지 범위 · 테이블 테두리 · 사람 · 짐을 겹침, 테두리 색 = 지금 신호등 | 실시간 |
| 판정 근거 | 범위 안 사람 · 짐 수, 비운 시간, 초록불까지, 부재 확인 중(10초) · 재석 확인 중(2초) 표시 | 1초 |
| 상태 기록 · 스냅샷 | 켠 뒤부터의 상태 띠, 상태가 바뀐 순간의 모자이크 스냅샷 (1일 뒤 삭제) | 바뀔 때 |

- 판정은 1초마다, 카메라 화면은 판정과 따로 실시간으로 보냅니다. 그래서 사람이 움직이면 박스가 최대 1초 늦게 따라옵니다.
- 실시간 화면에서도 사람은 모자이크합니다. 박스가 늦게 따라오는 만큼 **사람 박스보다 25% 넓게** 가립니다. 첫 판정 전에는 사람 위치를 몰라 화면을 보내지 않습니다.

## 성능 확인 창 (`성능확인.py`)

내 카메라(웹캠)로 **판정 1초 + 화면 실시간**이 이 컴퓨터에서 어느 정도로 도는지 눈으로 확인하는 창입니다.

```bash
python 성능확인.py                    # 웹캠 0번
python 성능확인.py --source 1차.mp4   # 영상으로 확인
```

- 창 왼쪽 아래: 화면 fps, 마지막 판정 시간(SAM 범위 갱신 포함 여부), 판정 결과가 몇 초 전 것인지, 장치·모델, **이 컴퓨터로 1초 간격 판정이 가능한 룸 수**
- 시작하면 초록불 시간을 묻습니다 (위 "초록불 시간 입력"과 같음).
- 키: `q` 종료 · `m` 사람 모자이크 켜기/끄기 · `t` 판정 모델 바꾸기 (기본 YOLO26s ↔ 파인튜닝 v2)
- 끝나면 모델별 판정 시간 중앙값·p95와 실제 판정 간격을 출력합니다.

**웹캠은 기본 YOLO26s로 시작합니다.** 파인튜닝 v2는 천장에서 내려다본 스터디룸 사진으로만 학습해서, 정면 웹캠 앞 사람을 거의 못 찾습니다. 같은 웹캠 화면 14장으로 비교한 결과입니다 (2026-10-23).

| 모델 | 사람 검출 (신뢰도 0.35 이상) | 최고 신뢰도 |
|---|---|---|
| 파인튜닝 v2 | 14장 중 2장 | 대부분 0.06 이하 |
| 기본 YOLO26s | **14장 중 14장** | 0.91~0.93 |

파인튜닝은 학습한 각도(천장)에 맞춰지는 대신 다른 각도에는 약해집니다. 실제 설치는 천장 카메라라 운영에는 v2를 쓰고, 영상 파일을 넣으면 성능 확인 창도 v2로 시작합니다.

### 성능 확인 창 숫자가 발표(초당 55장)보다 낮은 이유

성능 확인 창은 "1초 간격으로 판정 가능한 룸 약 14~17개"로 나옵니다. 발표의 "초당 55장"과 달라 보이지만, **잰 범위가 다릅니다.** 같은 노트북(RTX 5060 Laptop GPU)으로 잰 값입니다.

| 측정 | 룸 1개(1장)에 걸린 시간 | 1초에 판정 가능한 룸 | 들어간 일 |
|---|---|---|---|
| 발표 슬라이드 (서버 사양 실측) | 18.1ms | 약 55개 | YOLO 추론만 |
| 10/23 YOLO만 (배터리 전원) | 27.5ms (그중 추론 27.0ms) | 약 36개 | YOLO 호출 전체 (전처리 · 추론 · 후처리) |
| 10/23 판정만, 창 없음 (배터리 전원) | 29.4ms | 약 34개 | YOLO + 감지 범위 겹침 계산 + 짐 판정 |
| 룸 14개 동시 처리 (아래 표) | 30~32ms | 약 30개 | 판정 + 화면 복사 + 기록 |
| **성능 확인 창** (10/23, 배터리 전원) | 57~71ms | 약 14~17개 | 판정 **+ 같은 프로그램에서 화면을 초당 27장씩 그림** |

1. **성능 확인 창은 판정과 결과 화면을 같이 보여 줘서 느립니다.** 판정과 화면 그리기(모자이크, 글자, 창 출력)가 한 프로그램 안에서 CPU를 나눠 써서, 판정이 그만큼 기다립니다. 같은 웹캠 화면으로 창 없이 판정만 하면 29.4ms(약 34개)로, 창이 있을 때의 절반 이하입니다. 실제 서버는 창 없이 판정만 하므로, 이 창의 룸 수는 **가장 불리한 조건에서 잰 값**입니다.
2. **10/23 측정은 노트북이 배터리 전원(전원 모드 "균형 조정")이었습니다.** 그래서 YOLO 추론만도 27ms로 발표 때 18.1ms보다 느렸습니다. 노트북 GPU는 전원 상태에 따라 속도가 크게 달라집니다. 발표 때 측정의 전원 상태는 기록이 없어, 전원을 연결하고 다시 재 볼 필요가 있습니다.
3. **두 모델의 속도 차이는 오차입니다.** 기본 YOLO26s와 v2는 구조가 같습니다. 한 번은 기본 57ms · v2 71ms, 다른 번은 기본 70ms · v2 61ms로 순서가 뒤집혔습니다.
4. 가장 불리한 성능 확인 창에서도 룸 14개를 1초 안에 판정할 수 있어, 발표의 결론(1초 간격 판정 가능)과 어긋나지 않습니다.

## 룸 14개 동시 처리 결과 (2026-10-23)

1차.mp4를 룸 14개처럼 복제해 60초 동안 1초마다 판정했습니다. 팀 노트북(RTX 5060 Laptop GPU), 입력 960.

| 항목 | 값 |
|---|---|
| 한 바퀴(14개 룸) 처리 시간 중앙값 | **453ms** |
| p95 | 708ms |
| 룸 1개당 | 32.4ms |
| 1초 간격 실시간 판정 | **가능** (p95가 1,000ms보다 짧음) |

- 룸 1개당 32.4ms는 모델 추론(18.1ms)에 화면 복사, 감지 범위 계산, 기록이 더해진 값입니다.
- 가장 긴 바퀴는 5,643ms였습니다. 여러 룸이 동시에 빈 룸이 되어 **SAM으로 감지 범위를 새로 딴 바퀴**입니다. SAM은 설치할 때와 테이블이 움직였을 때만 돌기 때문에 운영 중에는 드물지만, 그 순간에는 판정이 몇 초 늦어질 수 있습니다.
- GTX 1060급 실측과 실제 카메라 14대(RTSP)로 한 시험은 아직 하지 않았습니다.
