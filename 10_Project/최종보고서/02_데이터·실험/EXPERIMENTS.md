## 3. 추론 위치 비교 실험 설계

같은 판정 프로그램을 노트북(서버 방식)과 라즈베리파이(내부 방식)에서 각각 돌려, 추론 위치만 바꿨을 때 정확도와 속도, 운영 조건이 어떻게 달라지는지 잰다. 결과를 보고 실제 설치 방식을 정한다. 서버 방식은 서버 담당이, 내부 방식은 라즈베리파이 담당이 맡는다.

바꾸는 것은 연산 장치(노트북 MPS, 라즈베리파이 CPU)뿐이다. 모델 YOLO26s, 입력 크기 960, 임계값 0.30, 감지 영역 zone_1차.json, 판정 규칙, 판정 코드 server.py는 고정한다.

할 일

1. 라즈베리파이 모델과 RAM을 확인한다. YOLO26s는 노트북 CPU 실행에서 약 0.5GB를 썼다.
2. 같은 영상 비교: 1차.mp4를 양쪽에서 같은 명령으로 돌리고 판정 기록을 비교한다. 입력이 같으므로 장치 차이만 남는다.
3. 실시간 비교: 같은 룸에서 같은 시나리오(앉기, 짐 두고 나가기, 돌아오기)를 방식별로 한 번씩 한다. 동시에 돌리면 라즈베리파이가 스트림 전송과 추론을 같이 해서 서버 방식 결과가 흔들리므로 따로 한다.
4. 끊김 시험: 실행 중 Wi-Fi를 1분 끊고 신호등 동작을 기록한다.

일정: 10/20 미팅 전 1, 2번. 10/21 연결 테스트 때 3, 4번.

| 지표 | 재는 법 | 제안 기준 |
|---|---|---|
| 판정 일치율 | 정답 구간과 신호등 색이 같은 프레임 비율 | 99% 이상 |
| 1장 처리 시간 | 판정 기록의 프레임별 시간 (평균, 최대) | 30초 이하 |
| 빨강 반응 시간 | 사람이 들어온 시각부터 첫 빨강까지 | 1분 이하 |
| 최대 메모리 | 실행 중 메모리 최댓값 | 기기 RAM의 70% 이하 |
| 끊김 시 동작 | 4번 시험 결과 | 초록불이 잘못 켜지지 않음 |
| 개인정보, 확장 비용 | 영상이 룸 밖으로 나가는지, 룸 14개일 때 필요한 장비 | 기준 없이 비교만 함 |

처리 시간 기준 30초는 빨강 반응 1분에 맞춘 값이다. 2프레임 연속으로 잡혀야 빨강이 켜지므로 1장에 30초면 반응에 최대 1분이 걸린다. 제안 기준은 모두 미팅에서 합의가 필요하다.

결정 필요: 라즈베리파이에서 YOLO26s가 기준을 넘지 못할 때

- 양쪽 모두 YOLO26n으로 바꾼다. 연산량이 26s의 4분의 1(5.5 GFLOPs)이지만, 1차.mp4에서 사람이 있는 프레임 3장을 놓쳤다(5절).
- 방식마다 돌릴 수 있는 가장 좋은 모델을 쓴다. 각자 최고 성능을 내지만 모델과 위치가 함께 바뀌어 차이의 원인을 나눌 수 없다.
- 라즈베리파이용 형식(NCNN 등)으로 변환한다. 속도는 오를 수 있지만 실행 엔진이 달라져 변수가 하나 늘어난다. 속도가 얼마나 오르는지는 확인 필요.

## 4. 생성형 데이터 실험 (Stable Diffusion 인페인팅)

엎드린 사람 데이터가 부족해서, 08_Gen_Synthetic_data 실습과 같은 stable-diffusion-v1-5/stable-diffusion-inpainting으로 1차.mp4의 빈 방 프레임(8:00)에 엎드린 사람을 그려 넣었다. 자리 주변 512x512만 잘라 그리고 마스크 안쪽만 원본에 다시 붙이므로, 그린 자리 밖은 실제 화면 그대로다. 코드와 자리 박스는 synthetic/에, 검수 시트는 image/07~09에 있다.

방법

- 자리 4곳은 1차 영상에서 사람이 앉았을 때 YOLO11x가 잡은 박스로 정했다. A 왼쪽, B 위쪽, C 아래쪽은 실제로 사람이 앉은 자리이고, D 오른쪽은 아무도 앉지 않아 직접 정했다.
- 사람이 그려졌는지는 CLIP(openai/clip-vit-base-patch32)으로 먼저 거른다(synthetic/filter.py). YOLO와 다른 모델로 거르기 때문에 YOLO가 놓치는 이미지도 버려지지 않는다. 시험 생성 16장에서 기준 0.9가 눈 판정과 16장 모두 일치했다.
- 최종 판정은 사람이 눈으로 한다. 판정은 각 out 폴더 labels.json의 review에 적었다(sleeping, person_other, artifact, none).
- 1장 생성에 약 70초가 걸렸다(MPS, 25~30스텝).

| 회차 | 설정 | 생성 | 사람 있음 | 엎드린 사람 | 엎드린 장 YOLO 검출 (0.35) |
|---|---|---|---|---|---|
| 시험 | 공통 지시문, 옷차림 4가지 | 16 | 5 | 3 | 11x 3/3, 26l 3/3 |
| 2차 | 자리별 방향, 부정 지시문, 남녀 x 옷차림 4가지 | 32 | 24 | 16 | 11x 16/16, 26l 16/16 |
| 어려운 장면 | 외투, 후드, 담요로 머리와 몸을 가림. D 마스크를 책상 쪽으로 옮김 | 32 | 30 | 21 | 11x 21/21, 26l 20/21 |

- 자리별 방향을 지시문에 넣자 C(뒷모습)가 시험 0/4에서 2차 8/8로 사람이 그려졌다. 그중 3장은 다리만 있거나 얼굴만 떠 있는 깨진 이미지였다. D는 2차에서도 1/8이었다.
- 2차에서 CLIP 0.9 거르기는 엎드린 16장을 모두 남기고 사람 없는 8장을 모두 버렸다. 깨어 있는 자세 4장과 깨진 이미지 3장은 거르지 못했다.
- 2차 엎드린 16장에서 YOLO11x는 평균 0.80, 최저 0.50(C 뒷모습)이고, YOLO26l은 평균 0.83, 최저 0.38(A 패딩 옆모습)이다. 뒷모습은 26l이, 패딩 옆모습은 11x가 높아서 어느 쪽이 낫다고 말할 수 없다.
- 두 모델이 이미 다 잡는 이미지로는 학습해도 고칠 실수가 없다. 생성 데이터가 학습에 쓸모 있으려면 YOLO가 실제로 놓치는 장면을 만들어야 해서, 머리와 몸을 가린 어려운 장면을 따로 생성했다.
- 어려운 장면 엎드린 21장에서 YOLO11x는 평균 0.83, 최저 0.38로 모두 잡았다. YOLO26l은 평균 0.82였지만 후드를 쓰고 흰 베개에 엎드린 여성(A_5)을 0.14로 놓쳤다. 같은 장면에서 11x도 0.38로 기준선 바로 위였다. 지금까지 만든 합성 이미지 80장 중 YOLO가 놓친 엎드린 장면은 이 한 장뿐이다.
- D 마스크를 책상 가장자리 쪽으로 옮기자 D에서도 8장 중 7장에 사람이 그려졌다(엎드린 장면 5장). 사람이 놓일 책상 면이 마스크 안에 있어야 Stable Diffusion이 사람을 그린다.
- 의자에 외투만 걸린 이미지(어려운 장면 A_2)는 두 모델 모두 사람으로 잡지 않았다. 짐만 남은 장면의 오탐 예시로 쓸 수 있다.
- 결론: 사전학습 YOLO11x가 합성 엎드린 장면 40장(시험 3, 2차 16, 어려운 장면 21)을 모두 잡았으므로, 생성 데이터로 추가 학습할 필요성은 낮다. 15종으로 넓혀 보면 YOLO26s도 40장을 모두 잡았다(5절). 생성 이미지를 학습에 쓴다면 A_5처럼 놓치는 경우만 골라 모아야 하는데, 80장 중 1장꼴이라 생성 비용(1장 약 70초) 대비 효율이 낮다. 후드를 쓰고 엎드린 장면은 실제로 촬영해 확인할 항목으로 남긴다.
- 합성 이미지의 검출률은 실제 재현율이 아니다. 모델 선택과 임계값은 실제 영상으로 정한다.
