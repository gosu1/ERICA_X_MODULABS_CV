# 10_Project: 스터디룸 알박기 감지

스터디룸에 짐만 두고 30분 넘게 자리를 비운 상태를 카메라로 감지해 문 앞 신호등으로 알린다. 이 폴더의 코드는 1차 회의 보고서(2026-10-15) 기준으로 만들었다.

폴더: 0_기획서(PRFAQ.md, 처음 기획), 1주차(1차 회의 보고서), 2주차(2차 회의 보고서), 프로젝트_최종(최종보고서 = 최종 보고서·발표 자료, IC-PBL = 팀원 각자의 자기성찰지 자리, 수정_기획서 = PRFAQ.md 최종 반영본, 통합 코드모음). 통합 코드모음 아래에 01_판정코드(server.py 판정 본체, capture.py 프레임 수집, zone.py 감지 영역, compare.py 모델 비교, realtime/live.py 실시간 인식 화면), 02_데이터·실험(EXPERIMENTS.md, DATASETS.md, synthetic/ Stable Diffusion 합성, image/ 실험 이미지·실제 사람은 모자이크), 03_모델(알박기_yolo26s_v2.pt), 04_BASE_MODEL(모델 비교·파인튜닝 정리, SAM 감지 범위, 관리자 대시보드 데모), 05_라즈베리파이, 06_통합실행(카메라 여러 대 통합 실행). 모델 선택 근거, 실험 수치, 추론 위치 비교 실험 설계, 생성형 데이터 실험 결과는 프로젝트_최종/통합 코드모음/02_데이터·실험/EXPERIMENTS.md에 있다.

## 기준 문서

0_기획서/PRFAQ.md(처음 기획)와 1차 회의 보고서는 기준이 다르고, 코드는 회의 보고서를 따른다. 코드를 고칠 때는 회의 보고서 기준을 유지하고, PRFAQ 기준으로 바꿔야 할 것 같으면 먼저 사용자에게 확인한다.

| 항목 | 회의 보고서 (코드) | PRFAQ.md |
|---|---|---|
| 상태 | 빨강 사용중, 노랑 비움 30분 미만, 초록 비움 30분 이상 | OCCUPIED, AWAY, ABANDONED(60분), VACANT |
| 입력 크기, 임계값 | 960, person 0.30 | 640, person 0.3 |
| 감지 영역 판정 | 사람 박스 중심이 다각형 안 | bbox 넓이 50% 이상이 ROI 안 |
| 화면 저장 | 상태가 바뀐 순간만 사람을 모자이크해 1일 보관 | 디스크에 저장하지 않음 |
| 짐 검출 | 하지 않음 | 짐 클래스로 AWAY와 VACANT 구분 |

## 현재 결정과 이유

- 모델 YOLO26s. 15종을 같은 시험에 모두 돌렸을 때 s 크기(약 10M 파라미터)에서 모든 지표가 가장 높았고, 파라미터가 6배인 YOLO11x와 비슷했다. 연산량이 11x의 9분의 1이라 라즈베리파이에서도 같은 모델로 비교할 수 있다. 근거는 EXPERIMENTS.md 5절.
- 임계값 0.30. 1차 영상(원본 프레임) 빈 방의 사람 점수 최고 0.12와, 합성 엎드린 장면의 최저 0.36 사이에 있다.
- 26s는 팀의 실제 엎드린 사람 사진 6장으로 아직 시험하지 않았다. 같은 계열 26n이 그 시험에서 최하위였으므로, 사진이나 실제 촬영으로 확인하기 전까지는 확정이 아니다. 대안은 YOLO11x(사진 최저 0.93)다.
- 감지 영역은 테이블 검출 대신 zone.py로 다각형을 직접 지정한다. COCO dining table은 15종 중 YOLO11l만 0.35를 넘겼고, 큰 모델일수록 오히려 못 잡았다.
- 2프레임 연속 검출해야 사용중으로 본다. 30분 타이머는 사람이 한 번만 잡혀도 초기화되므로, 한 번 잘못 잡힌 박스가 알박기를 계속 가린다.
- 스트림이 끊긴 시간은 자리 비움 시간에 넣지 않는다. 끊김을 "사람 없음"으로 세면 공부 중인 방에 초록불이 켜진다.

## 진행 중: 추론 위치 비교 실험

같은 server.py를 노트북(서버 방식, MPS)과 라즈베리파이(내부 방식, CPU)에서 돌려 비교한다. 추론 위치만 바꾸고 모델, 입력 크기, 임계값, 감지 영역, 판정 규칙, 입력 영상은 고정한다. 라즈베리파이에서 그대로 돌리려면 server.py에 세 가지가 더 필요하다.

- 판정 기록 CSV에 1장 처리 시간 열을 추가한다.
- USB 카메라 번호(0)를 source로 받는다. 지금 capture.frames()는 파일이 아닌 입력을 모두 스트림 URL로 연다.
- 내부 방식의 send_signal()은 GPIO로 LED를 켠다. 서버 방식은 지금처럼 `{"color": "red" | "yellow" | "green"}`을 HTTP POST로 보낸다.

## 실행과 검증

- 환경: Python 3.12에 `pip install ultralytics`. 가중치(*.pt)는 처음 실행할 때 자동으로 내려받는다.
- 같은 영상 검증: `python server.py 1차.mp4 --zone zone_1차.json --interval 2 --log log.csv`. 기본 설정에서 빨강 188장, 노랑 471장이 나오면 정상이다. 정답과 다른 3장은 사람이 들어온 첫 프레임 2장(2프레임 연속 확인 규칙)과 3:30에 사람이 화면 끝으로 나가는 순간이다.
- 시연할 때는 `--limit-min 1`로 초록 기준을 1분으로 줄인다.

## 주의

- 영상(1차.mp4 등)과 snapshots/에는 팀원 얼굴이 나온다. 이 저장소는 공개이므로 영상은 팀 카톡방으로 주고받는다. .gitignore가 *.mp4와 snapshots/를 막고 있다.
- compare.py의 "최대 메모리"에는 MPS가 GPU 쪽에 잡는 메모리가 빠져 있다. YOLO11x를 MPS로 돌리면 실제로 약 1.8GB를 쓴다.
- compare.py는 JPEG로 저장한 프레임을, server.py는 영상에서 바로 꺼낸 프레임을 쓴다. 대부분 차이는 0.01 이하지만 경계 프레임에서는 크게 갈릴 수 있다(YOLO26s가 같은 프레임에서 0.29와 0.56). 임계값 근처의 판단은 server.py 결과로 확인한다.
- 노트북 스왑이 가득 찼을 때 1장 처리 시간이 0.3초에서 5초까지 늘었다. 속도를 잴 때는 다른 앱을 닫고 잰다.
- zone.py의 클릭 화면은 아직 실행해 보지 않았다. zone_1차.json은 좌표 격자를 보고 직접 입력했고, 1차.mp4 카메라 화면(960x540) 기준이다.
- 실제 라즈베리파이 스트림과는 연결해 보지 않았다. 스트림 끊김은 노트북 안의 임시 MJPEG 서버로 시험했다.
