## 3. 추론 위치 비교 실험 설계

같은 판정 프로그램을 노트북(서버 방식)과 라즈베리파이(내부 방식)에서 각각 돌려, 추론 위치만 바꿨을 때 정확도와 속도, 운영 조건이 어떻게 달라지는지 잰다. 결과를 보고 실제 설치 방식을 정한다. 서버 방식은 서버 담당이, 내부 방식은 라즈베리파이 담당이 맡는다.

바꾸는 것은 연산 장치(노트북 MPS, 라즈베리파이 CPU)뿐이다. 모델 YOLO11x, 입력 크기 960, 임계값 0.35, 감지 영역 zone_1차.json, 판정 규칙, 판정 코드 server.py는 고정한다.

할 일

1. 라즈베리파이 모델과 RAM을 확인한다. YOLO11x는 노트북 CPU 실행에서 약 1.1GB를 썼다.
2. 같은 영상 비교: 1차.mp4를 양쪽에서 같은 명령으로 돌리고 판정 기록을 비교한다. 입력이 같으므로 장치 차이만 남는다.
3. 실시간 비교: 같은 룸에서 같은 시나리오(앉기, 짐 두고 나가기, 돌아오기)를 방식별로 한 번씩 한다. 동시에 돌리면 라즈베리파이가 스트림 전송과 추론을 같이 해서 서버 방식 결과가 흔들리므로 따로 한다.
4. 끊김 시험: 실행 중 Wi-Fi를 1분 끊고 신호등 동작을 기록한다.

일정: 10/20 미팅 전 1, 2번. 10/21 연결 테스트 때 3, 4번.

| 지표 | 재는 법 | 제안 기준 |
|---|---|---|
| 판정 일치율 | 정답 구간과 신호등 색이 같은 프레임 비율 | 99% 이상 |
| 1장 처리 시간 | 판정 기록의 프레임별 시간 (평균, 최대) | 30초 이하 |
| 빨강 반응 시간 | 사람이 들어온 시각부터 첫 빨강까지 | 1분 이하 |
| 최대 메모리 | 실행 중 메모리 최댓값 | 기기 RAM의 70% 이하 |
| 끊김 시 동작 | 4번 시험 결과 | 초록불이 잘못 켜지지 않음 |
| 개인정보, 확장 비용 | 영상이 룸 밖으로 나가는지, 룸 14개일 때 필요한 장비 | 기준 없이 비교만 함 |

처리 시간 기준 30초는 빨강 반응 1분에 맞춘 값이다. 2프레임 연속으로 잡혀야 빨강이 켜지므로 1장에 30초면 반응에 최대 1분이 걸린다. 제안 기준은 모두 미팅에서 합의가 필요하다.

결정 필요: 라즈베리파이에서 YOLO11x가 기준을 넘지 못할 때

- 양쪽 모두 작은 모델로 바꾼다. 비교는 공정하지만 서버 쪽 정확도 여유를 버린다. 1차.mp4에서는 YOLO11s도 오류가 0이었으므로 이 룸에서는 손해가 작을 수 있다. 다만 엎드린 사람 사진에서 11s의 최저 점수는 0.79로 11x(0.93)보다 낮았다.
- 방식마다 돌릴 수 있는 가장 좋은 모델을 쓴다. 각자 최고 성능을 내지만 모델과 위치가 함께 바뀌어 차이의 원인을 나눌 수 없다.
- 라즈베리파이용 형식(NCNN 등)으로 변환한다. 속도는 오를 수 있지만 실행 엔진이 달라져 변수가 하나 늘어난다. 속도가 얼마나 오르는지는 확인 필요.
